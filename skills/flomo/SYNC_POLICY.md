# flomo 技能同步策略

这份文档定义 `skills/flomo` 从原始 skill 同步到共享仓库时的边界。

## 目标

- 保留原始 skill 的行为更新
- 保护共享仓库里的泛化内容不被覆盖
- 避免把个人标签树、本机路径、个人示例重新写回共享版本

## 可同步内容

以下内容可以从原始 skill 直接同步，前提是不破坏共享仓库的泛化约束：

- `SKILL.md` 里的行为规则、流程步骤、错误处理、输出约定
- `scripts/` 里的通用脚本逻辑
- `references/` 里不包含个人标签树或本机路径的通用说明

## 受保护内容

以下内容属于共享仓库保护区，默认不允许被原始 skill 直接覆盖：

- 根 `README.md` 的中文仓库说明和安装说明
- `skills/flomo/README.md` 的中文介绍、安装方式和推荐插件
- `skills/flomo/references/wechat-reading.md` 中泛化后的标签模板
- 任何写死的本机路径、用户名、token、私有地址、个人标签树

## 同步规则

1. 先比较原始 skill 与共享仓库版本的差异。
2. 只接受明确属于原始 skill 行为变化的内容。
3. 如果差异落在受保护内容里，先泛化，再提交。
4. 如果无法判断是否属于个人内容，默认不覆盖，改为人工确认。
5. 同步后再次检查是否出现本机路径、个人标签树或其他可识别个人信息。

## 冲突处理

- 原始 skill 新增了个人标签路径时，改成模板化描述再合并。
- 原始 skill 新增了本机安装路径时，改成 `$env:USERPROFILE` 或仓库无关写法。
- 原始 skill 新增了个人示例时，改成中性示例或删掉。
- 原始 skill 新增了共享仓库已经定好的中文说明时，不回写覆盖。

## 实践建议

- 先同步 `SKILL.md`，再处理 `README.md` 和 `references/`。
- 共享仓库只保留一份权威的泛化说明。
- 若以后要自动化同步，先按这份策略实现白名单，而不是黑名单。
